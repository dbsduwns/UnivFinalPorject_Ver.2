## 3. DB 설계

### 3.1 테이블 목록 (총 18개)

**👤 인증/사용자**
- `users`: 사용자 정보 (이메일, 비밀번호 해시, 이름, 학과, 학번, 학년)

**📅 시간표 (6개)**
- `subjects`: 개설 과목 목록
- `courses`: 과목별 분반 정보
- `course_schedules`: 분반별 시간표
- `timetables`: 사용자 시간표
- `timetable_courses`: 시간표-강의 연결
- `wizard_selections`: 시간표 마법사 과목 선택

**📢 공지사항 (2개)**
- `notices`: 공지사항 목록
- `notice_reads`: 읽음 처리

**🏢 캠퍼스 (2개)**
- `buildings`: 건물 정보
- `rooms`: 강의실 정보

**🤖 AI 챗봇 (2개)**
- `chat_rooms`: 대화방
- `messages`: 대화 메시지

**🍱 학식 (2개)**
- `daily_menus`: 날짜별 학식
- `menu_items`: 메뉴 항목

**🔔 알림 (1개)**
- `notification_settings`: 알림 설정

**🎓 졸업 요건 (2개)**
- `graduation_standards`: 학과별 졸업 요건 기준
- `completed_courses`: 이수 완료 과목

### 3.2 주요 관계

```
users ──< timetables ──< timetable_courses >── courses >── subjects
users ──< wizard_selections >── subjects
users ──< notice_reads >── notices
users ──< chat_rooms ──< messages
users ──< completed_courses >── subjects
users ── notification_settings
buildings ──< rooms
courses >── rooms
daily_menus ──< menu_items
```

## 6. 인증 흐름

```
1. 회원가입
   이메일 + 비밀번호 + 이름 → bcrypt 해싱 → DB 저장

2. 로그인
   이메일 + 비밀번호 → 검증 → JWT 토큰 발급
   access_token (60분) + refresh_token (14일)

3. API 요청
   Header: Authorization: Bearer {access_token}

4. 토큰 만료 시
   refresh_token → 새 access_token 발급
```

## 7. 크롤링 명세

### 7.1 공지사항 크롤링

- **대상**: 강남대학교 공지사항 페이지
- **URL**: `https://web.kangnam.ac.kr/menu/f19069e6134f8f8aa7f689a4a675e66f.do`
- **방법**: Playwright로 동적 페이지 렌더링 후 크롤링
- **주기**: APScheduler로 1시간마다 자동 실행
- **중복 방지**: 제목 기준으로 중복 체크

### 7.2 크롤링 흐름

```
1. Playwright로 공지 목록 페이지 접속
2. a.detailLink 태그에서 제목, encMenuSeq, encMenuBoardSeq 추출
3. 각 공지 상세 URL로 이동
4. div.tbl_view 태그에서 본문 내용 추출
5. DB 저장 (중복 제외)
```
