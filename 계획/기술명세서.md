# KNU Campus Life 기술명세서

## 1. 시스템 개요

KNU Campus Life는 강남대학교 학생을 위한 통합 캠퍼스 앱이다. 백엔드는 FastAPI 기반 REST API로 인증, 공지사항, 식단, 셔틀 시간표, 강의/과목, 시간표, 개인 일정, 챗봇, **푸시 알림** 기능을 제공한다. 프론트엔드는 React Native Expo 기반 모바일 앱으로 구성하며, 현재는 주요 기능들의 실제 API 연동이 완료된 상태이다.

## 4. 주요 구현 구조

### 4.1 인증 및 권한

- 일반 이메일/비밀번호 회원가입과 로그인을 제공한다.
- 로그인 성공 시 access token과 refresh token을 발급한다.
- `/auth/me`는 현재 사용자 정보와 `is_admin` 값을 반환한다.
- 사용자 정보 수정 및 알림 설정 API가 구현되어 있다.

### 4.2 공지사항

- 개선된 `notice_crawler_v3`를 통해 본문 내 이미지까지 수집한다.
- 새 공지 수집 시 **해당 카테고리 알림을 허용한 사용자들에게 푸시 알림을 즉시 발송**한다.
- 공지사항 목록은 무한 스크롤 및 카테고리 필터를 지원한다.

### 4.3 식단

- 주간 식단표 이미지를 크롤링하여 날짜별로 저장한다.
- 새로운 식단표가 업데이트되면 **알림 허용 사용자들에게 푸시 알림을 발송**한다.

### 4.4 셔틀 시간표

- 최신 셔틀 시간표 PDF 링크를 수집하고 RAG 문서로 인덱싱한다.
- 새 시간표 등록 시 **푸시 알림을 발송**한다.

### 4.5 RAG 챗봇 및 채팅방 관리

- **채팅방 관리**: 채팅방 생성, 삭제, 이름 수정 기능이 구현되어 있으며, Drawer 메뉴에서 Long Press로 설정 모달을 띄울 수 있다.
- **자동 제목 생성**: 새 채팅방에서 첫 질문을 던지면 질문 내용의 앞부분을 따서 채팅방 제목을 자동으로 설정한다.
- **Empty State**: 채팅 메시지가 없을 때 추천 질문을 제안하여 대화를 유도한다.
- 공지사항, 셔틀, 학사일정, 학교 규정 데이터를 기반으로 답변한다.

### 4.6 푸시 알림 (Push Notification)

- **Backend**: Expo Push API를 사용하여 `NotificationSetting` 테이블에 저장된 토큰으로 알림을 전송한다. 크롤러 작업 완료 시 `notify_users_by_type` 함수를 호출한다.
- **Frontend**: 앱 실행 시 `expo-notifications`를 통해 권한을 요청하고 토큰을 획득하여 서버에 등록한다. 알림 클릭 시 해당 화면으로 이동하는 로직을 갖춘다.

### 4.7 Scheduler

- APScheduler를 통해 공지사항(1시간), 학식(매일 새벽 1시), 셔틀(12시간) 크롤링을 정기적으로 수행한다.

### 4.8 친구 시스템 및 시간표 공유 구조 (Friendship & Timetable Sharing)

- **상태 관리**: `PENDING`(요청 대기), `ACCEPTED`(친구 완료), `REJECTED`(거절)의 3가지 상태로 관리되며, 요청자-수신자 간 유니크 인덱스를 통해 중복 요청을 방지한다.
- **프라이버시 보호**: 시간표 열람 API 호출 시 요청자와 대상 사용자의 친구 관계(`ACCEPTED`)를 반드시 검증하며, 비인가 접근 시 403 Forbidden을 반환한다.
- **프론트엔드 UI**: 시간표 화면 상단 [친구] 버튼을 통해 친구 모달 진입, 친구 목록에서 탭 시 내 시간표와 동일한 포맷의 전용 주간 그리드 뷰어로 친구 시간표를 렌더링한다.

### 4.9 1:1 쪽지(메시지) 구조 (Direct Messaging)

- **대화 내역 관리**: 발신자/수신자 ID와 메시지 본문, 수신일시 및 `is_read` 플래그를 저장한다.
- **방 목록 집계**: `GROUP BY` 또는 최신 메시지 서브쿼리를 활용하여 대화 상대별 최신 대화 1건과 읽지 않은 메시지 개수를 계산하여 효율적으로 반환한다.

### 4.10 에브리타임 스타일 커뮤니티 구조 (Community)

- **익명성 보장**: `is_anonymous` 플래그를 두며, 익명 작성 시 작성자 고유 식별자는 감추고 "익명" 또는 게시글 내 댓글 순번(예: 익명1, 익명2, 작성자)으로 표시한다.
- **좋아요 중복 방지**: `post_likes` 테이블에 `user_id`와 `post_id`를 복합 유니크 키로 두어 1인 1회 추천만 가능하도록 보장한다.

  - 친구 검색, 요청, 수락/거절/취소, 목록, 삭제 API 구현

  - 프론트엔드 친구 관리 모달 및 친구 시간표 그리드 뷰어 컴포넌트 개발
- **Phase 2: 1:1 쪽지(메시지) 시스템**
  - DB 모델 `DirectMessage` 설계
  - 대화 목록, 대화 상세, 메시지 전송 및 읽음 처리 API 구현
  - 쪽지함 및 실시간/폴링 대화 UI 개발
- **Phase 3: 커뮤니티 및 게시판 시스템**
  - DB 모델 `Board`, `Post`, `Comment`, `PostLike` 설계
  - 게시판/게시글/댓글 CRUD 및 익명 처리, 좋아요 API 구현
  - 게시판 목록, 글 상세, 작성/수정, 댓글 UI 개발
- **Phase 4: 부가 고도화 과제**
  - Google 로그인 백엔드 로직 검증 및 보완
  - 공지사항 읽음 상태 API 구현
  - 졸업 요건, 기이수 과목, 위저드 선택 관련 실제 데이터 연동
  - 관리자 전용 데이터 관리 대시보드 UI
