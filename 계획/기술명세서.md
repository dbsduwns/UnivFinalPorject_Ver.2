# KNU Campus Life 기술명세서

> 기준일: 2026-11-11
>
> 구현 상태는 현재 저장소의 코드·마이그레이션·테스트를 기준으로 작성했다. 외부 API 키, Cloud Run 권한, Android 실기기 동작처럼 저장소만으로 확정할 수 없는 항목은 운영 검증 대상으로 표시한다.

## 1. 시스템 구성

```text
React Native Expo 앱 / 관리자 웹
          │ HTTPS REST
          ▼
FastAPI (Cloud Run)
   ├── Supabase PostgreSQL + Alembic
   ├── Qdrant Cloud (RAG 벡터)
   ├── Cloudflare Workers AI (LLM/임베딩)
   ├── Google Routes / Google Maps
   ├── TMAP (주소 검색·지오코딩)
   └── TAGO·서울·경기 버스 API
          ▲
Cloud Run Job + Cloud Scheduler (크롤링·동기화)
```

Cloud Run 파일시스템은 임시 저장소다. 운영 데이터와 벡터는 PostgreSQL·Qdrant에 저장하며, 셔틀 PDF를 장기 보관하려면 별도 객체 저장소가 필요하다.

## 2. 기술 스택

### 2.1 Backend

- Python 3.13, FastAPI, Uvicorn
- Pydantic v2, SQLAlchemy 2, Alembic, PostgreSQL 15
- `python-jose`, `passlib`/bcrypt, `python-dotenv`
- Playwright, BeautifulSoup4, pdfplumber, pytesseract
- APScheduler 및 Cloud Run Job용 배치 스크립트
- LangChain, HuggingFace/Sentence Transformers
- Qdrant Cloud, Cloudflare Workers AI, 선택적 Google Gemini provider

### 2.2 Frontend

- React 19, React Native 0.81, Expo SDK 54
- Expo Router 6, TypeScript 5.9
- TanStack Query, Axios, Zustand
- NativeWind/Tailwind CSS, React Native Reanimated
- `expo-notifications`, `expo-secure-store`, `expo-local-authentication`
- `expo-maps` Google Maps(Android 우선), `expo-location`, `expo-updates`

### 2.3 외부 연동

- 강남대학교 공개 웹 페이지: 공지·식단·셔틀·과목·학사일정·규정 크롤링
- Google Routes API: `TRANSIT`·`WALK`, `arrivalTime`, 경로 polyline 및 대중교통 단계
- Google Maps Android SDK: 앱 지도 표시
- TMAP Open API: 주소·POI 검색 및 지오코딩
- TAGO 및 서울·경기 버스 API: 정류장·노선·도착·차량 위치

### 2.4 운영

- Cloud Run API 서비스
- Cloud Run Job: `scripts/run_daily_crawlers.py`, `scripts/run_notice_crawler.py` 등
- Cloud Scheduler: 일일 크롤러·학사일정 동기화 실행

## 4. API 명세

### 4.1 공통

- 인증이 필요한 API는 `Authorization: Bearer <access_token>`을 사용한다.
- access token이 만료되면 클라이언트는 `/auth/refresh`로 갱신하고 새 refresh token도 저장한다.
- 401은 인증 실패, 403은 권한 부족, 404는 대상 없음, 409는 중복·상태 충돌, 429는 호출 제한, 502는 외부 서비스 오류에 사용한다.

## 5. 주요 구현 구조

### 5.1 인증·보안

- `auth.py`와 `security.py`가 access/refresh JWT를 발급·검증한다.
- refresh DB 세션은 해시된 `jti`, 세션 ID, 만료, 폐기 상태, token version을 보관한다.
- Google OAuth identity는 별도 보관하고 기존 이메일 계정과 자동 병합하지 않는다.
- 학생 인증 대기 계정은 허용된 인증·계정 설정 API만 이용한다.
- 운영 비밀값은 Cloud Run Secret Manager 연결로 주입한다.

### 5.2 크롤링·RAG

- 크롤러는 원본 출처 키와 중복 방지 기준으로 데이터를 upsert한다.
- 공지·식단·셔틀·학사일정·규정 문서를 Qdrant에 색인한다.
- `QdrantDocumentStore`가 컬렉션 생성·upsert·삭제·검색을 담당한다.
- AI 봇은 질문 의도에 따라 메타데이터 필터를 적용하고, 규정은 PostgreSQL 데이터도 함께 사용한다.
- 일일 수집은 Cloud Run Job에서 순차 실행하며, 변경이 있을 때만 알림을 발송한다.

### 5.3 채팅·알림

- 일반 채팅은 `Room`, `RoomParticipant`, `RoomMessenger`로 1:1·단체방을 표현한다.
- `is_muted`는 사용자별 방 알림 차단 상태다.
- `UserPresence`는 앱 전경 여부, 활성 방, 마지막 heartbeat를 저장한다.
- 동일 방을 최근 전경에서 보고 있는 수신자는 메시지 푸시를 받지 않는다.
- 푸시 payload에는 메시지 본문을 넣지 않고 방 ID·발신자 ID 등 최소 정보만 전달한다.

### 5.4 통학 경로

1. `CommuteProfile`과 대표 시간표를 조회한다.
2. Asia/Seoul 기준 오늘의 가장 이른 수업과 건물 좌표를 결정한다.
3. 목표 도착시각을 `수업 시작 - departure_buffer_minutes`로 계산한다.
4. Google Routes `TRANSIT` 요청에 `arrivalTime`을 전달한다.
5. duration, 거리, GeoJSON polyline, 단계·환승·정류장 정보를 Pydantic 모델로 정규화한다.
6. 셔틀 설정이면 기흥역-이공관 후보와 탑승 여유시간을 조합한다.
7. 버스 단계는 정류장·노선·지역 정보를 이용해 TAGO 또는 서울·경기 API와 연결한다.
8. 실시간 정보는 캐시와 자체 호출 상한을 적용하고, 실패 시 예정 정보만 유지한다.

지도 화면은 `expo-maps`의 `GoogleMaps`를 사용한다. 캠퍼스 건물 탐색 상태와 `guidanceActive` 등교 안내 상태를 한 화면에서 전환하며, 홈 `CampusRouteCard`는 같은 지도 화면으로 진입해 안내를 시작한다.

```text
backend/
├── app/
│   ├── core/          # 보안, AI, 벡터 저장소, 알림, 외부 HTTP

│   ├── routers/       # FastAPI 라우터

│   └── services/      # 도메인·외부 API 서비스
├── alembic/versions/
├── scripts/           # Cloud Run Job·운영·검증 스크립트
├── tests/
└── deploy/cloudrun/

frontend/knu/
├── app/
│   ├── (auth)/        # 로그인·가입·학생 인증
│   └── (app)/         # 홈, 공지, 식단, 셔틀, 시간표, 지도, AI, 친구, 채팅, 커뮤니티

├── src/components/
├── src/hooks/
└── src/utils/
```

## 7. 테스트 및 운영 검증

- 백엔드: `backend/tests`에서 인증, CRUD, 권한, 채팅, 커뮤니티, RAG, 크롤러, 통학·교통, Cloud Run Job을 검증한다.

- 프론트: `cd frontend/knu; npm run lint` 및 TypeScript 검사
- 운영 전: `/health`, `/health/db`, `/docs`, 로그인, 주요 목록·AI·채팅·커뮤니티·통학 경로를 확인한다.
