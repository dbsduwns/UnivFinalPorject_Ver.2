# KNU Campus Life 요구사항

## 0. 최종 기준 및 변경 이력 (2026-11-03)

본 문서의 배포 기준은 Google Cloud Run 백엔드, Supabase PostgreSQL, Qdrant Cloud 벡터 저장소, Cloudflare Workers AI이다. Oracle VM 및 Oracle 전용 Docker·환경·백업 파일은 프로젝트에서 삭제했으며 Cloud Run 배포 문서를 정본으로 사용한다. 프론트엔드는 React Native Expo 앱이며 지도는 `expo-maps` Android Google Maps를 우선 지원한다.

인증 정책은 다음과 같다.

- 서비스 이용 대상은 강남대학교 학생이며, 회원가입 과정에서 강남대학교 이메일 OTP 인증을 필수로 수행한다.
- Google OAuth 성공만으로 정식 서비스 접근을 허용하지 않는다. Google 로그인 후 학생 이메일 인증을 완료하면 정식 access/refresh token을 발급한다.
- 같은 이메일의 기존 계정과 Google 계정은 자동 연결하지 않는다. 기존 계정 로그인 후 별도의 계정 연결 절차를 거쳐야 한다.
- access token과 refresh token은 `type`을 분리하고, `refresh_sessions`의 `session_id`·해시된 `jti`·만료·폐기 상태·`token_version`을 검증한다. 정상 갱신 시 refresh token도 함께 회전한다.
- 사용자의 학교 포털 학번·비밀번호는 수집하지 않는다. 크롤링 계정이 필요한 기능은 관리자/서비스 계정으로 제한하고 Secret Manager에서 관리한다.

삭제·정리된 레거시 구성: Oracle 배포 문서 및 스크립트, Oracle용 Docker Compose/Dockerfile, Oracle 전용 requirements와 환경 예시를 삭제했다.

## 1. 프로젝트 개요

KNU Campus Life는 강남대학교 학생을 위한 통합 캠퍼스 앱이다. 공지사항, 식단, 셔틀 시간표, 강의/과목, 시간표, 개인 일정, AI 챗봇, **푸시 알림**, **첫 수업 기반 등교시간 역산 및 통합 지도 안내**, 향후 졸업 관리 기능을 제공한다. 백엔드는 FastAPI 기반 REST API로 구현하고, 프론트엔드는 React Native Expo 기반 모바일 앱으로 구현한다.

### 1.1 등교시간 역산 및 통합 지도 기능의 목적과 의의

- 대학생은 첫 수업 시작시각이라는 고정된 도착 목표가 있지만, 대중교통 운행시각과 환승·도보시간을 직접 역산해야 한다.
- 시스템은 대표 시간표의 오늘 첫 수업, 수업 건물 위치, 사용자가 설정한 도착 여유시간을 결합하여 수업에 늦지 않기 위한 추천 출발시각을 직관적으로 제공한다.
- 단순 평균 이동시간 차감이 아니라 Google Routes API의 대중교통 `arrivalTime` 검색을 사용하여 목표 도착시각에 맞는 실제 운행 경로와 출발시각을 조회한다.
- Google 지도 경로와 공공데이터포털(TAGO)의 실시간 버스 도착정보를 결합하여 사용자가 별도 지도 앱과 버스 앱을 오가는 불편을 줄인다.
- 캠퍼스 건물 탐색, 교내 보행 안내, 등교 대중교통 안내를 하나의 지도 화면에서 제공하여 통학부터 강의실 이동까지 이어지는 사용자 경험을 만든다.
- Google 경로 데이터는 Google 지도 위에 표시하고, Google 및 공공데이터 출처를 명확히 구분하여 표시한다.

## 2. 기능 요구사항

### 2.1 사용자 인증 및 계정 관리

- 사용자는 이메일, 비밀번호, 이름으로 회원가입을 시작할 수 있으며, 정식 계정 활성화에는 강남대학교 이메일 OTP 인증이 필요하다.
- 사용자는 이메일과 비밀번호로 로그인할 수 있다.
- 로그인 성공 시 access token과 refresh token을 발급한다.
- 사용자는 본인의 프로필 정보(이름, 학과, 학번, 학년 등)를 수정할 수 있다.
- 현재 사용자 조회 응답에는 관리자 여부(`is_admin`)가 포함되어야 한다.
- 관리자는 일반 사용자와 같은 로그인 API를 사용하되, 로그인 후 권한과 UI가 다르게 동작해야 한다.
- Google 로그인은 OAuth 검증 후 학생 이메일 인증 대기 상태로 진입한다. 인증 전에는 일반 기능 API를 사용할 수 없다.
- 기존 동일 이메일 계정과 Google 계정은 자동 연결하지 않으며, 기존 계정 로그인 후 명시적인 계정 연결 절차를 제공한다.
- 인증이 필요한 API에 토큰이 없거나 유효하지 않으면 401을 반환한다.
- 관리자 권한이 필요한 API에 일반 사용자가 접근하면 403을 반환한다.

### 2.2 알림 설정 및 푸시 알림

- 사용자는 기기별로 푸시 알림 토큰을 등록할 수 있다.
- 사용자는 마이페이지에서 각 알림 항목(공지사항, 식단, 셔틀버스)에 대한 수신 여부를 개별적으로 설정할 수 있다.
- 시스템은 새로운 공지사항이 크롤링되면 알림 허용 사용자들에게 즉시 푸시 알림을 발송한다.
- 시스템은 새로운 주간 식단표가 업데이트되면 알림 허용 사용자들에게 푸시 알림을 발송한다.
- 시스템은 새로운 셔틀버스 시간표가 등록되면 알림 허용 사용자들에게 푸시 알림을 발송한다.

### 2.3 관리자 권한

- 공지사항 크롤링, 수정, 삭제는 관리자만 수행할 수 있다.
- 식단 크롤링은 관리자만 수행할 수 있다.
- 강의 HTML import와 학과별 강의 크롤링은 관리자만 수행할 수 있다.
- 셔틀 시간표 크롤링은 관리자만 수행할 수 있다.
- 프론트엔드는 `is_admin` 값에 따라 일반 사용자 UI와 관리자 UI를 분기해야 한다.

### 2.4 공지사항

- 시스템은 강남대학교 홈페이지 공지사항을 크롤링해 DB에 저장할 수 있다 (이미지 포함).
- 시스템은 카테고리별 공지사항을 수집할 수 있다.
- 사용자는 공지사항 목록을 조회하고, 상세 내용을 확인할 수 있다.
- 공지사항 목록은 카테고리 필터링과 키워드 검색을 지원한다.

### 2.5 식단

- 시스템은 주간 식단표 이미지 URL을 크롤링해 날짜별로 저장한다.
- 사용자는 날짜 기준으로 식단 이미지를 조회할 수 있다.

### 2.6 셔틀 시간표

- 시스템은 최신 셔틀 시간표 PDF 링크를 크롤링하여 저장한다.
- 사용자는 최신 및 과거 셔틀 시간표 목록을 조회할 수 있다.

### 2.7 강의/과목 및 시간표

- 시스템은 전 학과 개설강좌 HTML을 파싱하여 과목 및 강의 데이터를 자동 구축한다.
- 사용자는 본인의 시간표를 여러 개 생성하고 관리할 수 있다.
- 사용자는 시간표에 강의 또는 개인 일정을 추가할 수 있으며, 시스템은 시간 충돌 여부를 검사한다.
- 대표 시간표 설정 기능을 제공한다.

### 2.8 AI 챗봇 및 채팅방

- 사용자는 여러 개의 채팅방을 생성하고 관리(수정/삭제)할 수 있다.
- **채팅방 제목 자동 설정**: 새 채팅방에서 첫 질문 전송 시, 질문 내용을 바탕으로 채팅방 제목이 자동 생성된다.
- **가이드 UI**: 메시지가 없는 채팅방에서 추천 질문을 제공하여 대화를 유도한다.
- 시스템은 RAG(Retrieval-Augmented Generation) 방식을 통해 공지사항, 셔틀, 학사일정, 규정 데이터를 바탕으로 답변한다.

### 2.9 졸업 관리 및 수강 설계 (향후 고도화)

- 졸업 요건 조회, 기이수 과목 등록, 졸업 진단 위저드 기능을 제공할 예정이다.

### 2.10 친구 및 시간표 공유 (Friendship & Timetable Sharing)

- 사용자는 학번, 이름, 이메일로 다른 사용자를 검색하여 친구 요청을 보낼 수 있다.
- 사용자는 받은 친구 요청을 수락하거나 거절할 수 있으며, 보낸 요청을 취소할 수 있다.
- 서로 수락된 사용자들은 친구 목록에서 확인할 수 있으며, 친구 관계를 해제(삭제)할 수 있다.
- 사용자는 친구 목록에서 친구를 선택하여 해당 친구의 시간표(대표 시간표 또는 학기별 시간표)를 주간 그리드 형태로 열람할 수 있다.
- 친구 관계가 맺어지지 않은 사용자의 시간표는 조회할 수 없다 (프라이버시 보호).

### 2.11 1:1 쪽지 및 메시지 (Direct Messaging)

- 사용자는 친구 목록 또는 게시글(익명/실명)을 통해 상대방에게 1:1 쪽지를 보낼 수 있다.
- 쪽지함에서 대화 상대별 최근 메시지와 안 읽은 메시지 수를 확인할 수 있다.
- 대화 상세 화면에서 시간순 메시지 내역을 조회하고 메시지를 전송할 수 있으며, 진입 시 자동으로 읽음 처리된다.

### 2.12 커뮤니티 및 익명 게시판 (Community & Boards)

- 자유게시판, 비밀게시판, 새내기게시판, 정보게시판 등 다양한 주제의 게시판을 제공한다.
- 사용자는 게시글을 작성, 수정, 삭제할 수 있으며, 익명 작성 여부(`is_anonymous`)를 선택할 수 있다.
- 사용자는 게시글에 좋아요(공감)를 누를 수 있으며 중복 좋아요는 방지된다.
- 게시글에 댓글을 작성할 수 있으며, 댓글 역시 익명 작성을 지원한다.
- 게시글 목록 검색(키워드) 및 페이지네이션/무한 스크롤을 지원한다.

### 2.13 등교시간 역산 및 Google 통합 지도 안내 (Commute Guidance)

#### 통학 프로필과 목표 도착시각

- 사용자는 집 주소, 교내 셔틀 이용 여부, 수업 시작 전 도착 여유시간을 설정할 수 있다.
- 시스템은 대표 시간표를 우선 사용하고, 대표 시간표가 없으면 최신 시간표에서 오늘의 가장 이른 수업을 조회한다.
- 첫 수업 건물의 위치정보를 목적지로 사용한다.
- 목표 도착시각은 `첫 수업 시작시각 - 도착 여유시간`으로 계산한다.
- 첫 수업 전에는 추천 출발시각을 제공하고, 첫 수업이 시작된 뒤에는 현재 시각 기준 예상 이동시간을 제공한다.
- 오늘 수업이 없거나 통학 프로필 또는 건물 좌표가 없으면 사용자가 이해할 수 있는 별도 상태와 안내문을 제공한다.

#### Google 기반 대중교통 경로 계산

- 시스템은 Google Routes API의 대중교통 모드와 `arrivalTime`을 사용하여 목표 도착시각 이전에 도착 가능한 경로를 조회한다.
- 홈 화면에는 추천 출발시각, 예상 도착시각, 총 이동시간, 환승 횟수, 주요 노선을 요약하여 표시한다.
- 상세 경로에는 도보·버스·지하철 구간, 승하차 정류장, 구간별 출발·도착시각과 경로선을 포함한다.
- Google API 장애 또는 경로 없음 상태를 구분하며, 실시간 부가정보 조회에 실패하더라도 기본 Google 경로는 유지한다.
- 교내 셔틀 이용 시에는 수업 전 도착 가능한 셔틀을 먼저 선택하고, 셔틀 탑승 여유시간을 고려하여 집에서 셔틀 정류장까지의 출발시각을 역산한다.

#### 단일 지도 화면과 길안내 전환 UI

- 기존 `campus-map.tsx`의 Kakao 지도를 Google 지도로 교체한다.
- 지도 화면은 캠퍼스 탐색과 등교 안내를 별도 페이지 또는 별도 라우트 모드로 분리하지 않고 하나의 화면 상태에서 제공한다.
- 일반적으로 지도 탭에 진입하면 캠퍼스 건물, 편의시설, 현재 위치와 교내 탐색 기능을 표시한다.
- 지도 화면에 `등교 길안내` 버튼을 제공하고, 사용자가 버튼을 누르면 오늘의 추천 대중교통 경로를 같은 지도 위에 표시한다.
- 홈 화면의 `CampusRouteCard`에서 `경로보기`를 누르면 동일한 지도 화면으로 이동한 뒤 등교 길안내를 즉시 시작한다.
- 안내 중에는 `안내 종료` 또는 이에 준하는 UI를 제공하고, 종료하면 경로와 실시간 차량 표시를 제거한 뒤 기본 캠퍼스 탐색 상태로 돌아간다.
- 사용자는 대중교통 전체 경로와 단계별 안내를 확인하고, 선택한 구간 또는 정류장을 지도에서 강조할 수 있다.
- 교내 건물을 선택하면 현재 위치부터 해당 건물까지 Google 보행 경로를 조회하여 같은 지도 위에 표시한다.

#### 실시간 버스 정보

- Google 경로의 버스 노선번호, 승차 정류장명 및 좌표를 공공데이터포털(TAGO)의 도시코드·정류장 ID·노선 ID와 매칭한다.
- 매칭에 성공하면 승차 정류장의 버스 도착예정시간과 남은 정류장 수를 표시한다.
- 지원되는 지역과 노선에서는 노선별 실시간 버스 GPS 위치를 지도 위의 차량 마커로 표시할 수 있다.
- 실시간 정보는 길안내가 활성화된 동안에만 일정 주기로 갱신하며, 화면 이탈 또는 안내 종료 시 갱신을 중단한다.
- 노선 매칭 실패, 제공 지역 제한 또는 호출 한도 초과 시에는 Google의 예정 출발시각을 대체 정보로 표시한다.

## 3. 비기능 요구사항

- **보안**: 비밀번호는 해시로 저장하고 JWT access/refresh 용도를 분리한다. refresh token은 DB 세션과 jti를 이용해 회전·재사용 탐지를 수행한다.
- **자동화**: APScheduler를 사용하여 정기적으로 데이터를 수집한다.
- **안정성**: 크롤러 실행 시 학교 서버 부하를 고려하여 순차적으로 작업을 수행하고 중복 수집을 방지한다.
- **사용자 경험(UX)**: 앱 실행 시 푸시 알림 권한을 요청하며, 대량 목록 렌더링 시 성능 최적화를 적용한다.
- **확장성**: Alembic을 통한 DB 마이그레이션 관리를 수행한다.
- **외부 API 보안**: Google Routes 서버 키와 지도 표시용 브라우저 키를 분리하고, API별 사용 제한과 호출 한도를 설정한다. 기존 Gemini용 `GOOGLE_API_KEY`와 지도 키를 공유하지 않는다.
- **지도 데이터 준수**: Google Routes 결과는 Google 지도 위에서만 시각화하고 Google Maps 및 TAGO 출처를 명확히 표시한다.
- **실시간 호출 제어**: 버스 실시간 정보는 안내 화면이 활성화된 동안에만 제한된 주기로 갱신하고, 앱이 백그라운드로 전환되거나 안내가 종료되면 폴링을 중지한다.
- **장애 격리**: 실시간 버스 API 장애가 대중교통 기본 경로와 출발시각 계산을 실패시키지 않도록 부가정보 조회를 분리한다.
- **위치정보 보호**: 현재 위치는 지도 표시와 경로 계산에 필요한 범위에서만 사용하며, 불필요하게 장기 저장하지 않는다.
